# ACS Full-Series Data

This project contains harmonized American Community Survey (ACS) 5-year data at the national, state, and county levels. It includes the published full-series datasets through the 2024 ACS release, the inputs and R code used to build them, and scripts for validating and adding future ACS releases.

The project is ACS-only. Census decennial data and Census-processing scripts are not included.

## Quick start

Open `ACS_full_series.Rproj` in RStudio. This sets the project root as the working directory.

The supplied full-series datasets can be checked without a Census API key or an internet connection:

```r
source("02_r_scripts/validate_acs_national_full_series.R")
source("02_r_scripts/validate_acs_states_full_series.R")
source("02_r_scripts/validate_acs_counties_full_series.R")
```

The national validation script writes plots and supporting CSV files to `03_plots/`. The state and county validation results are printed in the R console. Review reported discrepancies rather than treating every flagged change as an error.

## Published datasets

The current datasets are:

- `01_data_output/final_acs_national_full_series_2024.csv`
- `01_data_output/final_acs_states_full_series_2024.csv`
- `01_data_output/final_acs_counties_full_series_2024.csv.xz`

The county full-series file is distributed in compressed `.csv.xz` format because the uncompressed CSV is larger than GitHub's file-size limit. Before using it, extract it to recover:

- `01_data_output/final_acs_counties_full_series_2024.csv`

R and Python can read `.csv.xz` files directly, but the project scripts and examples assume the uncompressed CSV is available. To keep the workflow consistent across national, state, and county files, extract the county file before running analyses that use the full ACS series.

`Year` is the ending year of an ACS 5-year period. For example, `2024` refers to the 2020-2024 ACS 5-year estimates.

Output naming follows these patterns:

- Single release: `final_acs_{geo}_{year}.csv`
- Full series: `final_acs_{geo}_full_series_{latest_year}.csv`

## Project structure

- `00_data_input/`: ACS variable mappings, lookup tables, geographic classifications, inflation source data, and an example Census API-key file.
- `01_data_output/`: published ACS full-series datasets and generated inflation factors. Annual update scripts also write intermediate and validation files here.
- `02_r_scripts/`: data-generation, maintenance, update, and validation scripts.
- `03_plots/`: plots and supporting data generated by the national full-series validation script.

Open `ACS_full_series.Rproj` before running scripts. Alternatively, set the project root (`ACS_full_series/`) as the R working directory. The scripts use relative paths based on `getwd()`.

## Output columns and missing values

Output columns generally use these suffixes:

- `_EST`: ACS estimate.
- `_MOE`: ACS margin of error.
- `_MOE_ADJ`: margin of error calculated or adjusted by this workflow.

The output files use two sentinel values that must not be interpreted as genuine negative measurements:

- `-888888888`: the estimate or margin of error is unavailable.
- `-555555555`: the margin of error is unavailable while an estimate is present; the workflow also uses this code when a reported margin of error is zero.

`Year` is the ending year of the ACS 5-year period, and `Source` identifies that period. Geographic FIPS fields should be imported as text to preserve leading zeros. Variable descriptions and their ACS source IDs are provided in `00_data_input/acs_vars_wide_with_labels.csv`.

## Software requirements

Install R and the required packages:

```r
install.packages(c("tidyverse", "tidycensus", "readxl"))
```

An internet connection and a US Census Bureau API key are required when downloading ACS data or refreshing ACS lookup files.

## Census API-key setup

Request a key using the [US Census Bureau API key signup page](https://api.census.gov/data/key_signup.html). Then:

1. Copy `00_data_input/census_data_api.example.csv` to `00_data_input/census_data_api.csv`.
2. Replace the example text with the API key.
3. Keep the file as a one-line CSV with no column heading.

The scripts read the key with:

```r
census_data_api <- readr::read_csv(
  file.path(wd$data_input, "census_data_api.csv"),
  col_names = FALSE,
  show_col_types = FALSE
) |>
  dplyr::pull()

tidycensus::census_api_key(census_data_api)
```

Do not share or commit `00_data_input/census_data_api.csv`. Only the example file should be distributed.

## Main scripts

The scripts fall into three groups:

- **Validate supplied datasets:** `validate_acs_national_full_series.R`, `validate_acs_states_full_series.R`, and `validate_acs_counties_full_series.R` can be run immediately using the included outputs.
- **Download or rebuild data:** `acs.R` and `update_acs_lookup_files.R` require an internet connection and Census API key.
- **Annual update:** the `validate_acs_*_update.R` and `update_acs_full_series.R` scripts require newly generated single-release outputs in addition to the preceding full-series files.

Individual scripts:

- `acs.R`: downloads ACS estimates and builds national, state, and county outputs. It can build a single release or a full series from scratch.
- `acs_release_config.R`: defines the first and latest ACS release years used throughout the workflow.
- `functions.R`: contains shared functions used by generation, update, and validation scripts.
- `read_decile_aggregate.R`: reads county decile, aggregation, and state lookup inputs.
- `update_acs_lookup_files.R`: downloads ACS variable metadata for the configured releases.
- `check_latest_acs_release_mapping.R`: compares the existing variable mapping with the latest ACS metadata.
- `add_acs_lookup_labels.R`: attaches ACS concepts and labels to the variable mapping.
- `build_acs_inflation_factors.R`: creates inflation factors from the R-CPI-U-RS workbook.
- `update_acs_full_series.R`: appends a validated single-release output to the preceding full series.
- `validate_acs_*_update.R`: compares a new release with the preceding full-series data.
- `validate_acs_*_full_series.R`: checks the completed national, state, and county full-series outputs.

## Rebuilding the data

In `02_r_scripts/acs.R`:

1. Set `years` to one ACS release year to build single-release outputs, or to multiple years to rebuild a full series from scratch.
2. Set `run_national`, `run_states`, and `run_counties` to select the required geographic outputs.
3. Run the script from the project root.

Downloading county data takes substantially longer because counties are retrieved state by state.

By default, all geographic outputs are disabled. Before sourcing `acs.R`, select the required outputs by setting one or more of `run_national`, `run_states`, and `run_counties` to `TRUE`. Generated files are written to `01_data_output/`, and files with matching names will be replaced.

## Annual ACS update workflow

Follow these steps after the Census API publishes a new ACS 5-year release:

1. Update the latest series year in `02_r_scripts/acs_release_config.R`.
2. Run `02_r_scripts/update_acs_lookup_files.R`.
3. Run `02_r_scripts/check_latest_acs_release_mapping.R`.
4. Review `01_data_output/acs_var_mapping_latest_release_review.csv`.
5. Check variable IDs, concepts, labels, universes, and table changes. Update `00_data_input/acs_vars_wide.csv` and `00_data_input/acs_mapping_update_log.csv` where required. If the existing mapping remains applicable, extend it to the new release year.
6. Run `02_r_scripts/add_acs_lookup_labels.R` to rebuild `00_data_input/acs_vars_wide_with_labels.csv`.
7. Obtain the latest R-CPI-U-RS workbook, place it in `00_data_input/`, and run `02_r_scripts/build_acs_inflation_factors.R`.
8. In `02_r_scripts/acs.R`, set `years` to the new release year and enable the required geographic outputs.
9. Run `02_r_scripts/acs.R` to create the new single-release national, state, and county files.
10. Run `validate_acs_national_update.R`, `validate_acs_states_update.R`, and `validate_acs_counties_update.R`. Review all reported discrepancies before proceeding.
11. Run `02_r_scripts/update_acs_full_series.R` to append the validated release to the preceding full-series files.
12. Run `validate_acs_national_full_series.R`, `validate_acs_states_full_series.R`, and `validate_acs_counties_full_series.R` as final checks.
13. Retain the new full-series outputs and archive or remove temporary review files as appropriate.

The existing 2024 full-series datasets are the preceding-series inputs when updating to the 2025 ACS release.

## ACS variable mapping

`00_data_input/acs_vars_wide.csv` is the main mapping file. Each row represents a project variable, and each year or year-range column gives the ACS variable ID used during that period.

`00_data_input/acs_vars_wide_with_labels.csv` supplements the mapping with metadata from the annual ACS 5-year files in `00_data_input/acs_lookup/`. For a year-range mapping column, the description is taken from the latest available lookup year in that range; for example, `2022-2024` uses 2024 metadata.

The generated metadata fields include:

- `description`: combined ACS concept and label.
- `description_status`: whether the normalized description is stable across mapped years.
- `description_variants`: grouped substantive description variants.
- `description_variant_count`: number of distinct normalized variants.

A shared or similar description does not guarantee perfect comparability across releases. Review universe definitions, table changes, and variable IDs during each annual update.

## Noted mapping changes

- 2022: `B05006_139` represents Latin American-born population estimates.
- 2019: `B05006_130` represents Latin American-born population estimates.
- 2019: opposite-sex and same-sex spouse household variables were added using `B09019_014`, `B09019_018`, `B09019_005`, and `B09019_008`.
- 2015: `B05006_124` represents Latin American-born population estimates.
- 2013: health-insurance coverage type-count variables were added from `B27010`.
- 2012: detailed health-insurance coverage variables were added from `B27001`, `B27002`, and `B27003`.
- 2011: race/ethnicity-specific occupation-by-sex variables were added using `C24010A` through `C24010I`.
- 2010: Hispanic-origin variables moved from `B03002` to `B03003`; sex-specific foreign-born region variables were added from `B05008`; the Gini index was added from `B19083_001`; and several `C24010` occupation variables were renumbered or dropped.

## CSV and FIPS note

Excel may display `County_FIPS` values such as `01001` without the leading zero when a CSV is opened directly. This is an Excel display/import issue rather than a change to the raw CSV. Import FIPS columns as text when using Excel.
